# 120. 라우터블 기술자산 보안·검색 운영정책 v0.1
기준: 2026-11-03 / 적용 범위: Mac Studio 내부 기술자산 검색 v1.3
목표: 비밀정보는 보호하고, 일반 개발 자료는 검색·분석·재사용을 최대한 개방한다.

## 운영 원칙
1. 공개 여부가 아니라 **원본의 민감도**와 **행위의 비가역성**을 기준으로 판단한다.
2. 일반 코드·개발 문서의 검색, 분석, SHA-256 검증, 독립 AI 이해 검토는 승인 없이 진행할 수 있다.
3. 패스키·비밀번호·복구키·Firebase Admin SDK JSON·개인 인증키·민감한 고객 원본자료는 원문 검색 색인과 외부 공유 대상에서 제외한다.
4. 파일 조회와 인덱싱은 원본을 수정하지 않는다. **운영 Firestore 변경, 원본 삭제, 백업 교체, 배포**는 작업 전 범위·복구 경로를 확인한다.
5. GitHub, NAS, ChatGPT Library의 위치는 각기 구분한다. 파일명의 일치만으로 원본·버전·운영 검증 완료라고 주장하지 않는다.
6. 비밀정보 자동 검사에는 한계가 있다. 정규식 검사 통과를 완전한 기밀성 보증으로 해석하지 않는다.

## 검색 보안 등급
| 등급 | 범주 | 검색 정책 | 예시 |
|---|---|---|---|
| P0 | 인증·암호·접속 비밀 | 완전 제외 (경로/내용 색인 금지) | 개인 SSH 키, 패스키, 비밀번호, Admin SDK JSON |
| P1 | 고객 개인정보·실거래 원본·잠재적 비밀 포함 문서 | 기본 원문 제외, 승인 후 필요한 최소 범위만 활용 | 고객 CSV, 실제 정산 자료, 키가 포함된 코드 |
| P2 | 내부 설정·계보·보관본·검증 DB | 파일명·안전한 경로·크기·해시 등 메타데이터 위주 | JSON, XML, 압축본, SQLite, 보안 위험 미검토 자료 |
| P3 | 재사용 가능한 일반 기술 소스와 문서 | Mac 로컬 전용 내용 검색, 이메일/전화번호·식별번호 치환, 비밀 문자열 감지 시 원문 제외 | Kotlin/Java/Python/JS, 기술 원고, README |

## v1.3 구현 범위
- 시작 기준: AssetSearch v1.2의 2,272개 항목을 별도 SQLite DB로 복사. 이전 버전은 불변.
- 신규 색인: Mac StudioProjects 8개 지정 프로젝트. 다른 작업 폴더, 프로젝트, NAS는 자동 확장하지 않는다.
- 코드·문서: UTF-8 텍스트 최대 350KB, 파일당 최대 1MB. 민감 문자열 검사 통과 시 이메일·전화번호·주민등록번호 패턴 치환 후 로컬 DB에 색인.
- 설정 및 구조: JSON·XML·YAML·Gradle 관련 파일은 메타데이터만 색인.
- 비밀명칭 파일·폴더: 비밀번호, secret, credential, Admin SDK, oauth, token, key/certificate 등은 제외.
- 빌드 결과물·.git·node_modules·숨김 파일·심볼릭 링크는 순회/색인하지 않는다.
- 새 색인: `~/Library/Application Support/ROUTABL-AssetSearch/assets_v1_3.sqlite` (개인 계정 전용 권한).
- 소스 원본, GitHub 코드, Firebase, NAS 보관본, 기존 백업 작업은 변경하지 않는다.
- 현재 v1.3은 **1회 생성 실증판**이며 자동 재색인과 상시 웹 서비스는 아직 없다.

## 실제 점검 값 (2026-11-03)
- 대상 8개 프로젝트, 신규 3,247개 파일 색인, 총 검색 레코드 5,519개.
- 새 항목: 텍스트 검색 P3 1,998개, 메타데이터 검색 P2 1,249개.
- 민감 경로/파일명 95개 제외 (민감 내용 노출 없이 집계만 보관).
- DB 무결성 정상, 검색 HTTP 시험 완료, 시험용 서버 종료.
- 두 개의 기존 증거 파일 cloud_access.py 및 TransportStatusPolicy.kt는 v1.2 검증 해시를 유지했다.
- 이전 v1.1 NAS 자료의 본문에 대한 전체 보안 재감사는 이번 검증 범위에 포함하지 않는다.

## 되돌리기·보관
- 문제가 발견되면 v1.3 사용을 중지하고 v1.2 검색 DB와 웹 화면으로 돌아간다.
- 새 DB는 로컬 색인이며 암호화된 자동 백업 범위 밖에 있어 원본 보존의 대체물이 아니다.
- Mac 원본, NAS, GitHub, Library는 각기 계보 연결 대상으로 남기며 복사/수정 여부는 별도 감사한다.
- 앱 실제 동작과 Firestore 접근 권한은 검색 결과만으로 입증되지 않는다.
