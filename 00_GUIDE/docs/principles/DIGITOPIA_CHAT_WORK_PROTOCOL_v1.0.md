# Digitopia Chat·Work 양방향 협업 규칙 v1.0

### 1. 기본 운영

동일 번호의 `N번 Chat`과 `N-W번 Work`는 하나의 작업을 수행하는 협업 쌍이다.

- Chat: 설계, 대안 비교, 의사결정, 범위·승인 검토
- Work: 실제 조사, 파일 작업, 구현, 시험, 증거 확보
- 단순하고 명확한 후속 작업은 현재 모드에서 계속할 수 있다.
- 불필요한 모드 왕복은 하지 않는다.

### 2. Chat → Work

실제 실행이 적합한 단계에서는 다음을 제공한다.

1. Work 진행을 권장하는 이유
2. 현재 확정된 설계와 작업 범위
3. 기존 기술자산과 재사용 대상
4. 변경 금지 항목과 승인 경계
5. 성공 판정 기준
6. Work에 바로 입력할 수 있는 완결된 프롬프트

### 3. Work → Chat

실행 중 새로운 설계 결정, 주요 위험, 범위 확대 또는 중요한 대안 선택이 필요하면 다음을 제공한다.

1. Chat 검토가 필요한 이유
2. 완료된 작업과 검증 증거
3. 발견한 문제 및 미해결 항목
4. 선택 가능한 대안과 영향
5. Chat에서 판단할 질문
6. Chat에 바로 입력할 수 있는 완결된 프롬프트

### 4. 인계 원칙

- 상대 채팅이 전체 대화와 파일을 자동으로 알고 있다고 가정하지 않는다.
- 필요한 자산 ID, 경로, SHA-256, 증거, 결정 내용을 인계문에 명시한다.
- 이전 단계의 확정 사항을 임의 변경하지 않는다.
- 성공, 실패, 미검증을 구분한다.
- 검증된 결과는 기술자산 환류 후보로 기록한다.
- 실제 운영환경 변경은 승인된 범위에서만 수행한다.

### 5. 종료 규칙

각 주요 작업 단계가 끝날 때 현재 결과를 검토하고 다음 중 하나를 판단한다.

- 현재 Chat에서 설계 계속
- 현재 Work에서 실행 계속
- Chat → Work 인계
- Work → Chat 인계
- 검증 완료 후 종료

다른 모드로 인계할 때는 이유를 설명하고 복사 가능한 프롬프트를 반드시 제공한다.

최상위 원칙: 생각은 원대하게, 실행은 디테일하게.

## 적용 설명

### 역할, 인계 증거, 승인

Chat은 설계와 범위·승인을 검토하고 Work는 승인된 범위에서 실행과 검증을 맡는다. 실행 범위와 성공 기준이 확정되면 Work에 넘긴다. 실행 중 새 설계 결정, 주요 위험, 범위 확대 또는 중요한 대안 선택이 생기면 Chat에서 판단한다.

인계문에는 상대가 바로 확인할 수 있도록 관련 자산 ID, 실제 경로, 확인된 SHA-256, 시험 증거, 확정 결정과 남은 쟁점을 기록한다. 성공·실패·미검증은 따로 표시한다. 인계문에 기록된 실행 요청은 이전 승인 범위를 자동으로 확대하지 않는다.

### TI-01과 VI-01

- **TI-01**은 손실 영향과 재취득 가능성을 기준으로 무엇을 우선 보존·복원할지 정한다. CW-01은 합의된 규칙, 승인 및 실행 증거의 출처와 확인 상태를 남긴다. 보존과 실제 복원은 별도로 검증한다.
- **VI-01**은 공통 원본을 분리하고 파생 버전의 변경·실행·복원을 격리한다. CW-01의 확정 판본을 보존하고 이후 판본과 AI별 적용 지침을 별도 파일로 관리하는 데 이 원칙을 적용한다.

### 판본 관리와 AI별 적용

규칙을 개정할 때는 기존 v1.0을 보존하고 새 판본을 별도 파일로 만든다. 변경 사유, 이전 판본, 승인 근거, SHA-256을 연결해 기록한다. 운영 대장 반영은 별도 승인 범위를 따른다.

이 파일의 규범 구역을 공식 기술자산 원본으로 삼는다. ChatGPT 프로젝트 지침과 Claude 등 AI별 지침은 각 환경에 맞춘 적용본이다. 적용본에는 참조한 CW-01 판본과 해시를 기록하고, 불일치가 발견되면 차이와 출처를 확인해 검토한다. Step 2에는 다른 프로젝트 지침이나 Claude 설정의 변경 권한이 없다.
