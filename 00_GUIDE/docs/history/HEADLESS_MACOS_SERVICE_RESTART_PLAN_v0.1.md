# 120. 라우터블 기술자산 자동 백업 — macOS 안전 재개 운영 절차 v0.1

작성: 2026-11-03 KST

**현재 자동 백업은 켜지 않는다. 기존 로컬/NAS/Drive 예약 3개는 중지 유지.**

## 현재 가능한 작업

- 현재 승인된 Mac Studio 사용자 환경에서는 v2.1 로컬 AES-256 및 NAS 암호화 백업을 성공시킨 기록이 있음.
- 별도 진단기 00_GUIDE/ROUTABL_HeadlessAccessDiagnostics_v0_1.py의 check 명령은 13단계 메타데이터만 읽고 백업하지 않음.
- 현행 자산대장 v0.11에는 61개. 검증된 마지막 AES 백업은 v0.9 48개 기준이므로 최신 자료 61개가 모두 보호됐다는 주장은 할 수 없음.

## 자동 실행 재개 순서

1. 독립 서명된 macOS 앱과 전용 백그라운드 헬퍼를 분리 설계. Apple ServiceManagement/SMAppService 방식을 우선 검토.
2. 앱 설치와 백그라운드 실행은 사용자가 명시적으로 승인. 먼저 실제 백업을 수행하지 않는 접근 진단 작업을 한 번 실행.
3. 최초 실패 단계 ID 및 errno만 기록하고 즉시 중단. 동일 실행 자동 반복은 금지.
4. 어느 앱의 무엇에 macOS 권한이 필요한지 확인 후 필요한 앱에만 제한적으로 권한 승인. Python/Terminal에 전체 디스크 접근을 무차별 확대하지 않음.
5. 안전한 단발 로컬 AES-256 백업: 자산대장 및 선택 파일 SHA, 영수증, 소형 파일 격리 복원, 이미지 마운트 해제 확인.
6. NAS는 동일 회차 로컬 영수증과 연결. 증분 CAS를 사용할 때 기존 NAS 전체 기준 스냅샷은 삭제하지 않음.
7. 정상 완료·접근 거부·저장소 미연결·중복 실행 상황까지 시험한 뒤에만 신규 예약 설치/운영 승인.
8. Google Drive는 마지막 오프사이트 수단으로 별도 원격 해시와 복원 검증 후 판단.

## 금지 및 주의

- 반복 재시작을 유발한 과거 launchctl submit 시험 방식을 다시 사용하지 않음.
- Terminal에서 .command를 여는 이전 자동 예약을 다시 사용하지 않음.
- 중지된 3개 기존 예약을 무조건 활성화하지 않음.
- macOS 개인정보 보호 DB 직접 변경, 키체인 인증정보 추출, 백업 비밀번호 로그 저장 금지.
- NAS 기준 전체 스냅샷 삭제/이동/덮어쓰기 금지.

## 추후 새 앱 준비 후 사용자 확인

- 시스템 설정 → 일반 → 로그인 항목 및 확장 프로그램: 해당 앱이 백그라운드 동작을 요청하는지 확인.
- 시스템 설정 → 개인정보 보호 및 보안: 실제 외장 SSD/네트워크 저장소를 접근하려는 앱의 범위만 확인.
- 구체적 실패 지점이 파악되기 전에는 전체 디스크 접근 권한을 일괄 부여하지 않음.
