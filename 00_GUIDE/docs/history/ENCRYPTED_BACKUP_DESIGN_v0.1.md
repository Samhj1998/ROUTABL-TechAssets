# ROUTABL 암호화 백업 설계안 v0.1
기준: 2026-11-03 KST / 상태: 설계, 실행 미승인

## 실측 환경
Mac 외장 /Volumes/SSD2TB: APFS, Encrypted: No, FileVault: No.
기존 스냅샷 BASELINE_20261103_v0.1~v0.3에는 민감 코드·백서 원본을 제외한 관리 메타데이터만 복제.
기존 외장 SSD 데이터/파티션/설정은 일절 변경하지 않았다.

## 추천 방식
기존 SSD를 지우거나 파티션을 변경하지 않고, 해당 볼륨 안에 별도의
암호화된 APFS 디스크 이미지(sparsebundle 또는 실사용 환경에 적합한 동등한 암호화 컨테이너)를 만든다.
기술자산 원본 백업은 이 암호화된 컨테이너 안에만 보관하도록 한다.
백업 루트·스냅샷·해시 영수증·복원 테스트를 함께 관리한다.

## 사전 결정해야 할 것
- 암호화 컨테이너 용량 상한·증가 방식, 자동 잠금/마운트 운영 방식.
- 암호 입력·복구키 보관 정책(Keychain/별도 오프라인 수단), AI 응답·로그에 노출 금지.
- 실제 백업 대상: Mac 원본 전체 vs 선정 핵심자산, 비밀키·PII 추가 제외 기준.
- 백업 작업의 잠금 오류·디스크 분리·용량 부족시 중단/재시도 정책.
- 분리된 임시 위치에 복원하여 SHA-256 검증할 시험 기준.
- 기존 Synology/Google Drive에 같은 암호화 묶음을 복제할지 여부.

## 지양할 작업
- 외장 SSD 재포맷 또는 전체 볼륨 암호화 전환을 임의 실행하지 않는다.
- 비밀번호를 스크립트 인자·로그·ChatGPT·관리 파일에 저장하지 않는다.
- 암호화 설정이 없는데 '전체 기술자산 안전 백업 완료'로 표시하지 않는다.
- 암호화 컨테이너를 만들더라도 원본 비밀키의 복제 및 외부 전송은 따로 심사한다.

## 승인 게이트
실제 암호화 컨테이너 생성, 키·비밀번호 설정, 자동 마운트/복제 설정은 사용자 승인이 필요한 작업이다.
