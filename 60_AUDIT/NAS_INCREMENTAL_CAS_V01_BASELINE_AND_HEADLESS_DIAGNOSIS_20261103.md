# 120번 기술자산 — NAS 증분 저장 기준 등록 및 무인 실행 실패 분석

기록일: 2026-11-03 KST

## 1. macOS launchd 재시도·권한 점검
- 2026-11-03 21:45경 `com.routabl.assetbackup.v21.oneoffcheck` 실행이 약 10초 간격으로 6회 실패한 사실을 macOS 통합 로그로 확인.
- 표준 오류에는 매회 `PermissionError` 기록. 이 메시지만으로는 어떤 파일 접근에서 거부됐는지 식별할 수 없음.
- 점검 대상의 소유자는 UID 501로 정상이고, 파일·폴더에 계정 접근 권한이 있으나 **해당 결과가 launchd 실행 환경에서의 TCC 허가를 증명하지는 않음**.
- 시험 서비스는 이미 제거돼 있고, 기존 Mac/NAS/Drive 자동 백업 3개는 비활성화, v2.1 신규 예약 설정 2개는 미설치.
- 안전 실패 후 무인 재시도 명령을 실행하지 않음. 해당 실패 원인은 보안 정책/실행 환경 문제로 미확정.

## 2. 새로운 NAS 암호화 증분 기준
- 새로운 단독 프로그램: `~/ROUTABL-TechAssets/00_GUIDE/ROUTABL_NAS_ContentAwareBackup_v0_1.py`
- 기존 v2.1 성공 백업의 NAS 스냅샷 `NAS_MANUAL_ASSET_V21_20261103_214221_KST_24639`를 읽어 **SHA-256 증명된 141개 암호화 구성 파일을 기준 목록**으로 작성.
- 기준 목록 파일: `/Volumes/Dev_Assets/ROUTABL-TechAssets-Backup/snapshots/ROUTABL-Ciphertext-CAS-v0_1/manifests/CAS_ASSET_V21_20261103_214028_KST_24533.json`
- 이미 존재하는 NAS 암호화 구성 파일 **1,128,457,076바이트를 다시 복사하지 않고** 기준 위치 참조만 저장.
- 기준 등록 후 전체 141개 파일 해시 재검증 `VERIFIED` 통과.
- 동일 스냅샷의 다시 등록 시 `SNAPSHOT_ALREADY_INDEXED` 처리와 141개 해시 재검증 통과.
- 기존 NAS 전체 암호화 이미지·영수증·로컬 백업 원본 수정 없음.

## 3. macOS와 NAS 파일시스템 호환성
- 최초 기준 목록 확정 시 POSIX 하드링크(`os.link`)가 NAS 공유 파일시스템에서 실패해 새 매니페스트가 생성되지 않음.
- 같은 폴더에서 `os.rename` 지원을 **독립 시험**한 후, 새로운 증분 프로그램의 목록 확정 구문만 호환 방식으로 변경.
- 최초 실패 시 생성된 우리 프로그램의 임시 파일 1개를 확인 후 정리. 기존 데이터 삭제 없음.
- 이후 기준 목록 작성·전체 해시 검증 성공.

## 4. 가상 증분 업데이트 시험
- 격리된 임시 경로에서 가상 암호화 구성 파일 3개로 새 회차를 구성.
- 변경 1개 → 새 SHA-256 객체 1개만 저장.
- 동일한 내용 2개 → 기존 기준 파일 위치 참조 재사용.
- 이전 기준 파일 원본 바이트 유지, 같은 회차 중복 실행은 `SNAPSHOT_ALREADY_INDEXED`로 처리됨.
- 격리된 임시 시험 파일은 시험 종료와 함께 제거.
- **이것은 실제 새 AES 이미지 변경 회차를 NAS에 증분 전송한 결과는 아님.**

## 5. 기준 백업의 삭제 금지 의무
- 새 증분 매니페스트는 이전 전체 NAS 암호화 스냅샷의 파일을 직접 참조.
- 따라서 `NAS_MANUAL_ASSET_V21_20261103_214221_KST_24639` 전체 보관본은 이 참조 구조가 유지되는 동안 삭제/이동/덮어쓰기 금지.
- 보존·정리 자동화와 스냅샷 prune, 원본 제거 명령은 개발/실행하지 않음.
- 장기 사용 시 단일 기준 전체 백업 의존성과 SHA-256 객체 저장소의 성장을 관리하는 보존주기 정책 필요.

## 6. 이번 단계에서 실제 증분 회차 시험 중지 사유
- 실데이터의 새 회차를 시작하기 전 저장공간/기준 목록을 확인하는 원격 실행 요청이 정책 검사를 통과하지 못함.
- 동일 작업을 다른 명령으로 우회하지 않고 새 AES 스냅샷 생성 및 NAS 실데이터 증분 복제를 보류.
- 기존 성공 스냅샷은 **자산대장 v0.9 기준 3,282개 파일**과 NAS AES 이미지 141개 구성 파일.
- 현재 자산대장 v0.10의 58개 항목 및 그 이후 발생한 증분 프로그램·보고서는 해당 기존 성공 스냅샷에 포함된 것으로 주장하지 않음.
