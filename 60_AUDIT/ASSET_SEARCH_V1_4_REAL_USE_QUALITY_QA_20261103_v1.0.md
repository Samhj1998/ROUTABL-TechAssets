## 주요 결함 / 개발 우선순위
### P1-01. 두 글자 검색어가 통째로 무시됨
검색엔진 v1.1 기반 query()에서 len(t)>=3 조건을 요구함.
'정산'은 SQL로 310행, '고객'은 589행이 포함되어 있지만 검색 화면 결과는 0건.
실사용 영향 큼. 한글 2글자 및 짧은 영어/숫자 검색을 안전하게 허용할 별도 한도/랭킹 필요.

### P1-02. 정식 원본보다 테스트·과거 복제본 우선
TransportStatusPolicy 검색 상위에는 TransportStatusPolicyTest 및 ROUTABL-Control-Public-20261020 등의 파생 프로젝트가 나오지만, 등록된 DISPATCH-One-Android 본 프로젝트의 정책 원본이 top10에 없음.
기존 중복 제거 규칙은 동일 SHA-256을 하나로 묶고 다른 경로를 숨긴다. 전체 DB에서 동일 SHA 그룹 805개 발견.
파일 동일성과 원본 권위는 별개이므로 반드시 원본·GitHub 커밋·NAS 보존본을 함께 보여줘야 함.

### P2-03. 검색 상한과 화면 목록 제한
'SEARCH-01' SQL 실제 매칭 1,215행, 검색 로직은 한 용어에 LIMIT 500 적용.
화면은 최종 상위 10개만 보여주며 페이지 이동/결과 필터가 없다.
기술자산 대량 보관본이 우선 노출되므로 정확한 원본 찾기 어려움.

### P2-04. 한글·영문 프로젝트명 연계 미흡
'시니어'는 29건 검색되지만 top10은 Mac 원본 0개. 
'Senior'는 SQL 기준 704건, Mac 소스는 552건.
한글 요청과 ROUTABL-Senior-Driver 폴더를 연결할 별칭 색인이 필요.

### P2-05. 경로는 보이지만 즉시 열기가 어려움
검색 결과 화면이 파일 경로를 일반 텍스트로 표시하며 직접 열기 기능이 없다.
MAC::StudioProjects/ 같은 가상 경로는 Finder 절대 경로가 아니다.
직접 열람 기능을 만들 경우 원본은 읽기 전용이어야 하고 로컬 화이트리스트 경로 검증 필요.

## 현재 장점 및 검증 경계
- SQLite 빠른 읽기(샘플 검색 1–51ms), 코드/문서 위치 색인, 민감정보 메타데이터 분리.
- 원본·이전 DB 자동 보존, 새로고침 버튼·단일 서버·무인 자동 종료 검증은 기존 v1.4 감사에 기록됨.
- 실제 사용자 Finder 더블클릭 후 검색 화면 표시는 사용자가 확인.
- 사용자 계정의 채팅·메모리·Library 원본 전체가 5,519개에 포함된 것은 아니므로 작업 맥락이 모두 검색된다고 주장하지 않는다.
- 개인정보/키 검출은 정규식 기반으로 완전 무누출을 보장하지 않는다.
- 이번 QA는 검색 정확도 및 결과 표시를 점검한 것이며 앱 실기기/Firestore 프로덕션 로직을 검증한 것은 아님.
