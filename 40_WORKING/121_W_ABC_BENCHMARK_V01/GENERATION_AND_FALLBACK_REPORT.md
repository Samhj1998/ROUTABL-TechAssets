# 세대 변경과 폴백

평가용 합성 DB에서 35개 엔진·검사 조합 PASS. 전체 생성, 무변경, 삽입, 본문 변경, 배치, 제목·경로 변경, 상태만 변경, 삭제, FTS 행 누락, 문서/FTS 불일치, 미지원 DDL, MATCH 오류, 세대 교체, 트랜잭션 롤백, 복구 사본 논리 정합성을 확인했다. 후보별 전체 반환 객체 및 활성 후보 누락을 A 기준으로 대조했다.

- B는 WAL의 쓰기 커밋 후 같은 SearchSnapshot에서 이전 값을 유지했고 새 스냅샷에서 현재 값을 반환했다. 운영 수명주기에서 동일하게 오래 열린 스냅샷을 사용할 경우 갱신 가시성 정책이 필요하다.
- C는 갱신 후 `fresh_fts_state_for_verify`, inode 교체 후 `file_replaced` 재연결을 실제 기록했다.
- FTS 누락·불일치·미지원 스키마·MATCH 오류에서 두 후보가 A에 동등한 폴백 결과를 반환했다.
- 복구 사본은 SQLite integrity_check, FTS 내부 검사, docs/ft 양방향 rowid 및 필드 비교와 A 결과 대조를 통과했다. 운영 복구와 실제 동시 서비스의 운영 수명주기는 NOT_TESTED.
- 첫 평가용 WAL 시도는 읽기 연결 준비 순서로 실패했다. 평가 스크립트가 쓰기 연결과 checkpoint 수명을 명시하도록 고친 후 새로운 복제 DB에서 재현했다. 동결 후보 코드에는 변경이 없었다.

근거 `private/lifecycle.json`. 새 검증 비용과 교체 직후 외부 지연은 파일의 verify_ms 및 external_ms에 있다.
