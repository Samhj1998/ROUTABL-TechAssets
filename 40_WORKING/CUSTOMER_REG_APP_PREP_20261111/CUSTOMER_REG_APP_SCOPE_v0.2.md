## 등록 흐름 (런북 → 화면)
1. 캡처 선택 → 글자 인식 → 입력칸 자동 채움 (없는 값은 비움, 추측 안 함)
2. 주소 → 좌표. **지번과 도로명을 각각 좌표로 바꿔 거리 비교** (서로 대응 확인). 행정동(비산7동) 실패 시 법정동(비산동) 재시도
3. **중복 검사** — 폰에 있는 주소록 전체(약 1,970건)에서 기본 이름 / 전화 / 주소로 찾기
   - 없음 → **신규 등록 요청**
   - 같은 업체 (이름·주소 일치) → **기존 고객 보완 요청**: 바뀐 칸만 표시. 전화가 다르면 덮어쓰지 않고 전화2 제안 (조양염직, 안성다이텍 사례)
   - 같은 주소 다른 업체 / 같은 이름 다른 주소 → 별도 신규 (영진전사↔다른집, 은일니트↔은일섬유, 유성텍스타일 고령)
4. 기사가 화면에서 확인·수정 → 요청 저장 (`customerSubmissions`, new 또는 edit + baseData)
5. **저장 후 서버 재조회로 저장 확인** (런북 TA-04)
6. 관리자 검수·확정 → 변경 저널 반영은 기존 서버 함수가 처리

## 넣지 않는 것
- 배차·정산·영수증 / 기사가 공용 주소록 직접 쓰기 / 자동 제출

## 확인 필요 (사용자)
1. `(접수자확인)` `(층확인)` `(**번지확인)` 같은 확인 표기: 이름에 그대로 둘까, 뗄까
2. 관리자(사용자 본인)는 등록앱에서 검수 없이 바로 확정 저장할 수 있게 할까 (ChatGPT 방식처럼)
3. 다른 업체 번호로 의심되는 전화(안성다이텍의 053-259-2700): 메모에 "확인 필요"로만 남기는 규칙 유지?
