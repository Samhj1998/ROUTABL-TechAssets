# Digitopia 121 독립 분석 B

SHA-256이 일치한 `COMMON_ANALYSIS_PACKET_V01.md`, `COMMON_TEST_SPEC.md`, `SYNTHETIC_DEV_V01.json`, `SYNTHETIC_CORPUS_V01.json`을 사용했다. 코퍼스는 첫 80행만 확인했다. 표본 첫 문서의 `path`는 `00_SYNTHETIC/SIM-001.md`, `title`은 `수정색인보정`이다. 기존 회귀 기대값의 예는 R01의 `all` 범위에서 match/group/manual **89/57/1**이다. 확인하지 못한 입력 파일은 없다.

## 1. 현재 구조의 병목과 가설

| 항목 | 입력에서 확인한 사실 | 후속 실측에서 검증할 가설 |
|---|---|---|
| 문서 후보 추출 | M01–M02에 따르면 원문과 설정 별칭마다 path/title/tags/content의 포함 조건을 OR로 결합한다. 기존 LIKE 계획은 SCAN이다. path PK의 등호 탐색은 부분 문자열 조건의 대체가 될 수 없다. | 색인 가능한 선택적 검색어는 본문을 포함한 전수 대조를 후보 집합 검증으로 바꾸면 SQLite 준비·fetch 시간과 p95가 감소할 수 있다. 흔한 검색어와 별칭 확장이 많은 질의는 후보 합집합이 커져 오히려 느릴 수 있다. |

## 2. 우선 구현할 단일 개선안

**기존 FTS5 trigram으로 문서 후보만 줄인다.** FTS에서 path/tags/content 후보를 얻고, 기존 제목 포함 조건을 통과한 경로를 합친다. 원본 문서에서 v1.5의 전체 포함 조건을 다시 평가하고 기존 후처리로 넘긴다. 기존 색인에 제목을 추가하는 변경은 이번 후보에 필요하지 않다. 유효한 후보가 적을 때 효과를 기대할 수 있고, FTS와 제목 검색을 분리해 제목 전용 매치의 누락을 방지할 수 있다.

```text
terms = v15_expand_terms(query)  # 원문·별칭 및 순서를 기존 방식대로 구성
if not all_terms_have_proven_fts_coverage(terms, active_index):
    return v15_search(query, scope)

within one read snapshot:
    candidates = paths where v15_title_predicate(title, terms)
    for term in terms:
        candidates |= docs_paths_from_ft_match(bound_quoted_literal(term))

    rows = original_docs_at(candidates) where v15_document_predicate(terms)
    manual = v15_manual(query, scope)
    return v15_finalize(rows, manual, query, scope)
```

- **후보 누락 방지.** 각 확장 용어가 기존 path/tags/content 조건을 만족할 때 대응 FTS 행이 반드시 MATCH되어야 한다. MATCH의 과다 후보는 원본 조건으로 제거할 수 있다. MATCH가 놓친 행은 후단에서 복구할 수 없으므로, 기존 LIKE의 이스케이프·대소문자·정규화와 FTS 토크나이저의 포괄 관계가 확인된 용어만 보낸다. 문자 수는 바이트가 아닌 코드포인트로 판단하고 3자 미만이나 의미 보존이 확인되지 않은 용어가 하나라도 있으면 질의 전체를 기존 경로로 보낸다. 입력을 바인딩하고 MATCH 구문과 구분되는 인용 리터럴을 구성한다. 색인 부재·불일치가 확인되거나 MATCH 실행이 실패한 경우에도 기존 경로를 사용하고 그 사유를 집계한다.
- **연결과 일관성.** `ft.rowid`와 `docs.rowid`의 대응은 M02로 확인되지 않는다. 승인된 격리 DB에서 안정적인 대응을 확인한 키만 사용한다. path 키를 쓸 때도 FTS가 해당 값을 원본 그대로 돌려주는지 먼저 확인한다. 제목·FTS·원본 조회는 같은 읽기 스냅샷에 두고, 후보는 경로별로 합친 뒤 path PK로 원본에 접근한다. FTS·원본의 생성 및 갱신 동기화가 보장되는 DB 세대에만 적용한다. 일관성을 보장할 수 없으면 후보를 활성화하지 않는다.
- **비용.** 기존 FTS의 MATCH 조회·후보 합집합·PK 재조회 비용이 생기며 제목 검사 비용은 남는다. 후보 수 K가 전체 문서 N보다 작을 때 본문 재평가 비용이 N건 규모에서 K건 규모로 줄어들 수 있다. 제목 조회도 테이블 페이지를 읽을 수 있어 I/O 감소 폭은 미정이다. 별칭이 많거나 K가 N에 가까우면 후단 이득이 사라질 수 있다. 기존 FTS를 그대로 재사용할 수 있다면 새 영구 인덱스의 저장 증가량과 갱신 쓰기 증가량은 설계상 0이다. 실제 DB와 인덱스별 바이트, 질의 중 임시 공간과 전체 색인 시간은 별도로 비교한다.

## 4. 공통 규격에 따른 A 대비 평가와 판정

동일 Mac Studio·SQLite·격리 코퍼스·인자에서 A(v1.5)와 B를 비교한다. C에도 평가자가 같은 규격을 적용할 수 있다. 아래는 수행 계획이며 실측값은 없다.

1. **기존 계약.** 평가자가 보유한 R01–R09에서 9/9를 요구한다. match/group/manual 개수와 반환 순서·점수·페이지·중복 개수 및 위치·검증 상태를 A와 대조한다. FTS 경로가 활성화되는 사례에서는 점수화 전 원본 경로 집합도 대조해 후보 누락과 거짓 후보 처리 오류를 구분한다. 페이지는 첫 페이지와 경계·후속 페이지를 확인한다.
2. **합성 정확도.** 공개 개발 30건과 평가자 전용 보류 20건을 각각 집계한다. qrels 경로 매핑으로 그룹 ID를 정규화하고 grade 3/1/0을 적용하며 같은 그룹의 두 번째 반환부터 0점 처리한다. Recall@10, Precision@10, MRR@10, nDCG@10을 질의별로 계산해 macro 평균을 보고한다. Precision 분모는 10, MRR은 첫 관련 그룹 순위의 역수, nDCG는 `2^grade-1` 이득과 `log2(rank+1)` 할인이다. 빈 결과는 0으로 둔다. 대표 경로·SHA·status·provenance version과 중복 개수·위치·그룹 단일 반환을 함께 대조한다. 이 최적화에서 순위와 점수의 A 대비 동등성이 목표다. 초성과 최신판 등 A와 B가 함께 미달한 qrels는 절대 점수에서 유지하고 이번 변경의 회귀와 구분한다.
3. **질의 성능.** 질의별·유형별로 최소 30회씩 같은 타이머·반복 수를 적용한다. A/B 순서를 회전하고 단일 실행으로 측정한다. 새 프로세스 첫 호출·새 연결 반복·재사용 연결 반복을 구분하며 OS 캐시는 강제 비우지 않는다. HTTP end-to-end와 query 내부를 구분해 SQLite 준비·행 fetch, Python 후처리, 연결·직렬화를 계측한다. nearest-rank p50/p95, 실패·타임아웃, FTS 경로와 기존 경로 비중 및 후보 수를 보고한다. 질의 유형별 지연 악화가 전체 집계에 가려지지 않게 한다.
4. **색인 시간·저장.** 격리 데이터에서 full, 1건 변경, 배치 변경, 무변경, 삭제, 이름 변경을 시험한다. 소스 읽기·이전 DB 복제·SQL 쓰기·검증/교체를 나눠 재고 각 갱신 뒤 예전 경로와 새 경로의 결과를 확인한다. 같은 안정화 시점의 DB 총 바이트와 인덱스별 바이트를 비교하고 FTS shadow 테이블 비용은 FTS에 귀속한다. 측정 방법과 크기 산출 범위를 A/B에서 통일한다.
5. **채택·중단.** 9/9 및 계약 동등성, 합성 정확도 비악화, 갱신·삭제·이름 변경 뒤 동기화가 먼저다. 이후 평가자가 미리 정한 업무 유형별 p95 목표와 색인 시간·저장공간 허용량에 맞을 때만 채택한다. 해당 목표치는 공통 규격에 수치가 없어 이번 분석에서 확정하지 않는다. 후보 누락·정렬 회귀·동기화 불일치가 하나라도 재현되거나 선택적 질의에서 재현 가능한 p95 이득이 없으면 후보를 중단하고 A를 유지한다. 성능 이득이 일부 유형에만 있으면 승인된 목표와 전체 분포에서 그 비중을 평가해 판정한다.

## 5. 구현 범위와 불확실성

구현 후보의 범위는 문서 후보 추출 분기와 기존 경로로의 폴백이다. 실제 코드·운영 DB·FTS 연결/설정은 확인하지 않았다. 원본 LIKE 리터럴 처리, 정규화, rowid 또는 path 연결, 인덱스 갱신 방식, 제목 스캔의 실제 비용, 별칭 분포와 운영 latency는 미확인이다. 검증된 코퍼스 표본은 첫 80행이며 전체 코퍼스 구조나 운영 분포로 일반화하지 않았다. 운영 회귀는 기대 집계만 확인했고 실제 검색 문자열·결과 경로·보류 자료는 평가자 영역이다. 코드 구현, 회귀 실행, 성능 계측은 이 분석에 포함되지 않았다.
