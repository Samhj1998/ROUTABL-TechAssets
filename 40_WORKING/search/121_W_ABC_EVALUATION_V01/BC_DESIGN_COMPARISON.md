# 동결된 B/C 설계 비교

증거는 해시가 일치하는 `EVAL_ANALYSIS_B.md`, `EVAL_ANALYSIS_C.md`와 이번 평가자 실측이다. B/C 두 문서는 동일한 4개 입력에서 출발했다. 두 제안의 후보 단계는 모두 trigram 재사용, 제목 분기, A 판정 재적용을 목표로 한다.

| 기준 | B 동결안 | C 동결안 | Step 4-A 확인 및 후속 쟁점 |
|---|---|---|---|
| v1.5 호환성 | 단일 읽기 스냅샷을 명시하고 기존 함수와 manual 재사용 | 후보 SQL 분기를 넣고 기존 점수와 그룹 로직을 유지 | 실제 코드 및 완전 객체 비교는 Step 4-B 이후 |
| FTS5 | 리터럴 MATCH를 용어별로 조회하고 경로 후보 합집합 | 모든 용어를 하나의 MATCH OR로 묶고 SQL UNION 사용 | MATCH 리터럴 바인딩은 공통. B의 반복 SQL 왕복과 C의 UNION 임시 B-tree 비용을 분리할 것 |
| 포괄성 | 각 확장어의 포괄성이 입증된 경우에만 가속. 링크 키도 확인 후 선택 | quoted phrase와 3자 조건을 주 근거로 사용. path IN을 기본으로 제시 | 운영 5,519행의 `ft.path`는 경로+제목. C 의사코드의 path IN은 그대로 쓰면 누락. B도 최종 연결 키로 raw path를 택하면 같은 문제. 같은 스냅샷 `rowid` 대응을 검증 |
| 제목·경로·태그·본문 | 제목 분기와 전체 원본 조건의 재적용을 명시 | 제목 SQL과 FTS SQL을 합친 뒤 Python 재확인 예시 | 제목은 독립 열로 미색인이나 합성 `ft.path` 문자열에도 포함. 행 결합 경계·Unicode 과다 후보를 A의 SQL LIKE 의미로 제거. Python 재검사 시 casefold와 SQLite LIKE 차이를 시험 |
| 짧은 질의·별칭 | 원문과 모든 별칭 중 하나라도 안전하지 않으면 전체 폴백 | 3자 미만 확장어가 하나라도 있으면 전체 폴백 | 2자 한글 및 2자 별칭 각각 원래 일치 행 2건이 무방비 MATCH에서 빠짐. A 자체의 2~80자 입력 제한도 보존 |
| 한글·초성 | NFC/NFD와 혼합 문자를 시험하고 기존 초성 동작 유지 | 초성은 별도 단계. 경로 NFC/NFD 동작 불변 가정 | NFC/NFD 각각의 표본에서 LIKE와 MATCH 결과 수 일치. 초성 문자열 직접 포함과 초성 생성 검색을 구분. A 초성 0/10 기록 유지 |
| 점수·정렬·중복·페이지 | 후보 경로만 중복 제거하고 별칭 가중치, sort 및 25개 위치 상한 보존 | 원본 후처리 재사용과 UNION 뒤 재정렬 | 점수·순서·대표·페이지 경계 및 scope 완전 비교. 후보 단계 LIMIT 및 FTS 순위 배제 |
| SHA·provenance | 길이 64 SHA 그룹과 그 외 path, path+SHA provenance를 명시 | SHA-64 그룹·상태·provenance 유지, version 출처는 미확인 | 현행은 검증된 path+SHA 매핑이며 버전 자동 승격과 별개. 같은 점수 대표는 기존 tie-break 적용 |
| FTS 실패 대응 | 세대 불일치·오류·미입증 용어는 전체 A 폴백과 사유 집계 | 플래그와 건강검사, integrity-check·행수·표본 | 누락을 주입하자 native integrity-check는 통과. 설치본의 detail=none/column에서 4자 phrase는 오류. C의 ‘후보가 늘 뿐’ 가정은 반례 확인 |
| 구현 난이도 | Python 키 집합·PK 재조회·동일 스냅샷 제어 | 단일 SQL 후보·UNION·명시적 health 분기 | 실제 LOC·실패 분기 수 및 오류 경로는 미측정. 키 투영과 스냅샷 연결 방식에 따라 차이 |
| 예상 병목 | 용어별 MATCH, Python 합집합, PK 조회, 제목 스캔, 다건 후처리 | SQL UNION 중복 제거, 제목 스캔, 다건 재검사 및 Python 후처리 | 1,230행에서 제목은 기본 SCAN. C의 `d.* UNION`은 content까지 임시 구조에 넣는 형태. 어느 비용이 지배적인지는 구현 후 판단 |
| 색인·저장 비용 | 기존 인덱스 재사용으로 영구 증가량 0 예상 | 재사용이 우선, 제목 커버링 인덱스는 후속 선택지 | 0은 가설. 제목 인덱스 추가가 부분 문자열을 B-tree 범위 탐색으로 바꾸지는 않음. 임시 저장·갱신 비용은 별도 |
| 복잡도·유지보수 | 사전조건과 관측 항목이 명시적, 별도 집합/스냅샷 관리 필요 | SQL 집중, recheck 의미와 health 경계 명시 필요 | 각 구현의 diff, 실패 후 복구, 계측 가능성을 동등하게 리뷰 |

A의 과거 기준선은 9질의×30회 평균 126.89ms, p50 117.66ms, p95 207.52ms, 최대 277.12ms, SQLite 평균 115.70ms, Python/잔여 평균 10.60ms였다. R08의 Python/잔여 평균은 59.26ms였다. 9/9 객체 회귀 PASS와 별개로 합성 정확도 Recall/Precision/MRR/nDCG@10은 0.80/0.16/0.80/0.80이고 초성 0/10 FAIL이었다. 후보 성능·정확도와 우열은 모두 NOT_TESTED다.
