# ASSET-SEARCH-01 v1.5 공통 구현 사실 v01

Step 4-B에서 두 독립 구현에 동일하게 제공할 초안이다.

- 현재 `ft`는 FTS5 내부 콘텐츠 방식의 `fts5(path,tags,content,tokenize='trigram')`다. 운영 스냅샷과 공개 합성 fixture에서 각 ft 행은 동일 DB 세대의 `docs.rowid`와 대응했고 `ft.path = docs.path || ' ' || docs.title`였다. ft.path 값의 원본 경로 등호 연결은 유효하지 않다.
- 현재 trigram 기본 case_sensitive=0, detail=full. 3 Unicode 문자 미만은 MATCH로 포착되지 않는다. 원문 또는 별칭의 3자 미만, NUL이나 MATCH 오류, 미지원 스키마 또는 검증 실패 시 기존 질의 경로를 사용한다. case·기호·공백·Unicode 후보는 A의 바인딩된 `LIKE … ESCAPE '!'` 의미를 재검사한다. 기존 title 조건 및 manual, scope, 점수, 그룹, 상태·provenance, 페이지 계약을 보존한다.
- FTS 내부 검사와 docs/ft 교차검사는 범위가 다르다. 비교와 후보 처리에 동일한 읽기 스냅샷을 사용하고 검증된 색인 세대에만 가속한다. 사용자 원본, 운영 DB, 실제 회귀 질의 및 보류 자료는 구현 폴더로 연결하지 않는다.
- `A_V15_QUERY_REFERENCE.py`는 변경 없는 v1.5 질의 함수와 두 상수에 합성 fixture 바인딩만 덧붙인 참조다. 동일 디렉터리에서 합성 코퍼스 및 DB를 읽는다. 세션별 소스 사본에서만 변경한다.
- 필수 A 대비 9/9 객체 일치, 개발 30/보류 20 회귀 0, 4개 정확도 지표 비악화, 후보 누락 0, 색인 갱신/삭제/이름 변경 정합성. p95 전체 -20% 이상, 선택적 3자 이상 -30% 이상, 짧은·다건·폴백별 +10% 이내. 전체·증분 색인 시간 각 +10% 이내 원칙, 저장 +5% 이내. 동일 장치·환경에서 질의별 30회 이상 순서를 교차한다. 운영/보류 게이트는 평가자만 실행한다.
