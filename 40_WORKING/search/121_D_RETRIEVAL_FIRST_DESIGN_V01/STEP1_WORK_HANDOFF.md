## 6. 실험 설계
- 우선 **1,230건 합성 1배와 10,000건에 가까운 결정적 확장 세트**에서 구현/계측. 확장 자료는 기존 실거래·실문서가 아닌 합성 데이터만 사용한다.
- 정답 집합이 알려진 공개 개발 질의와 새로운 합성 초성·태그·다중태그·별칭·본문·혼합 검색 질의를 만들고 **기대 관련 5~6건**을 지정한다. 확장 및 질의 세트를 코드 실행 전에 고정하며 seed·해시를 기록한다.
- 후보에 정답이 하나라도 없으면 원인을 분석하고 Recall@6, Recall@20, MRR@6, 사용자에 제시한 후보 수, 누락 수를 기록한다. 공개 기존 A와의 객체 100% 일치가 목적은 아니다. 새 검색 품질은 별도 정답 기준으로 평가한다.
- p50/p95: 첫 검색, 연결 재사용, 캐시 적중/미적중, 파일 후보 선정, 문단 발췌. CPU·RSS·SSD I/O 가능 범위에서 측정한다.
- 토큰은 가능하면 실제 선택한 tokenizer의 입력량으로 기록하고, 불가하면 **문자 수/추정 토큰**으로 분리 표시한다. 전체 파일 대비 AI 전달 자료 크기를 비교한다. '0 AI 토큰 후보검색'과 '최종 AI 적용 비용'을 구분한다.
- 초기 합격 목표(연구 가설): 10,000건 근사 세트에서 **선별 단계 warm p95 100ms 이하**, 첫 검색 p95 별도, 5~6개 후보에서 실제 필요한 기술의 발견율은 표본별 보고. 이 수치는 사용자 실측으로 확정된 목표가 아니며, 달성 실패도 결과로 기록한다.
- 추가되는 색인 용량과 등록 1회·변경분 갱신 비용을 재고, 100회 읽기 / 1회 갱신 같은 읽기 우세 시나리오의 총 비용을 비교한다.
- 운영 HTTP, 동시 사용자, 원본 10,000건 실제 측정은 **NOT_TESTED**로 명시한다.
