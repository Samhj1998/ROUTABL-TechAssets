## 3. 핵심 가설과 시험 순서
속도 개선보다 **색인 품질 자체를 먼저 입증**한다.
1. 실제 열람 가능한 일반 기술자산 20~50건을 읽기 전용으로 선정하고 파일별 원본 위치 및 근거 섹션을 고정한다.
2. 각각의 자료에 대해 동일한 세 가지 '검색 가능성'을 비교한다.
   - I0 최소 색인: 파일명·경로·프로젝트·기본 날짜.
   - I1 키워드 색인: I0 + 제목·태그·초성·표기 변형·별칭·핵심 용어.
   - I2 경험·맥락 색인: I1 + **문제, 실패한 시도, 방향 전환 이유, 최종 판단, 해결 원칙, 적용 조건, 검증 근거, 연관 사례**.
3. **색인을 만들기 전에** 현업에서 실제 사용할 다양한 표현의 평가 질의와 정답 근거를 먼저 고정하고, 가능하면 색인 작성자와 평가자를 분리한다. 정답은 해당 자료 근거와 연결해 임의의 AI 추론으로 만들지 않는다.
4. I0/I1/I2에서 동일한 검색 코어·동일한 데이터·같은 질의 세트를 실행해 **어떤 추가 인덱싱이 실제 발견율 향상에 기여했는지** 비교한다.
5. 추가 색인에 필요한 등록 1회 처리시간·AI 입력/출력 토큰·저장 용량·사람 검토 시간을 실측 가능 범위에서 비교한다. 가능하지 않으면 `NOT_TESTED`. 속도를 위해 인덱싱이 부실해져서는 안 되며, 무한 분석도 금지한다.

## 4. 내용과 경험 색인 품질 규약

한 원본 문서에 여러 경험이 있으면 문서 1개를 단일 키워드 덩어리로 만들지 말고, **파일 경로를 공유하는 복수의 경험 카드**를 생성한다.
