# 파일시스템 경계 판정

- 홈은 모드 0750, 기술자산 저장소는 0700, 같은 Mac 사용자 UID 501에서 두 디렉터리 모두 읽기·탐색 가능했다. 실자산 파일은 접근 시험 대상으로 사용하지 않았다.
- 합성 작업 디렉터리에서 기본 동일 UID로 실행하면 절대경로, ../, 심볼릭 링크로 형제 디렉터리의 합성 파일 읽기가 가능했다. 형제 디렉터리의 합성 파일 생성·수정·삭제도 가능했다. **폴더만으로 접근 격리 FAIL.**
- input 모드 0500의 쓰기 차단 표시를 확인했다. 별도의 합성 읽기 전용 디렉터리 및 0400 파일에서 쓰기 차단을 직접 확인했다. 같은 소유자가 합성 디렉터리를 0700으로 바꿀 수 있었으므로 파일 모드만으로 소유자 프로세스를 강제 제한할 수 없다. 시험용 모드는 원복했다.
- 독립 macOS Seatbelt 프로필을 Python 테스트 프로세스에 적용했을 때 형제 합성 파일에 대한 세 읽기와 세 쓰기가 모두 차단됐다. 테스트 링크는 검사 직후 제거했다.
- 프로필은 합성 경로 하나의 데이터 읽기와 테스트 프로세스 쓰기를 제한하는 샘플이다. 실제 원본과 홈 전체의 읽기, CLI 내장 도구, Keychain, 서비스 자동 로딩 또는 Claude 셸의 실효 격리는 NOT_TESTED. 실사용에 적용할 프로필이 아니다.

후속 대안은 별도 macOS 표준 사용자 또는 파일·네트워크가 차단된 동등한 전용 실행 환경이다. 현재 UID의 Claude 프로세스 전체에 거는 격리도 별도 설계와 검증이 필요하다. 신규 사용자·권한 변경은 이번 승인 범위 밖이다.
