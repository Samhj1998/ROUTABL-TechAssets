# Step 4-C 공통 평가 승인안

대상 MacStudioui-MacStudio.local (`c377300b-a710-43a6-8169-f17e87175403`), macOS 27.2 arm64, Python 3.9.6, SQLite 3.54.0. 양쪽 최초 결과의 소스·시험·보고서 해시가 모두 고정됐을 때 Step 4-C 실행을 별도 승인해 달라. 한쪽이 미완료면 해당 구현과 동결을 먼저 마친다.

1. 운영 원본의 읽기 전용 해시를 재검증하고, 같은 로컬 평가용 스냅샷에서 A/B/C 운영 9질의 전체 객체·순서·점수·페이지·그룹·위치·provenance를 비교한다. 평가자 전용 보류 20질의 및 공개 개발 30질의는 별도 집계한다. 두 구현 AI에 운영 검색어·DB·보류 자료를 제공하지 않는다.
2. 평가자 전용 `EVALUATION_COHORT_PRIVATE.json`의 고정 50개 동등 가중치, 기존 선택도·질의 유형 및 운영 9개 별도 계층을 적용한다. `EVALUATION_BOUNDARY_AUXILIARY.json`의 다건·짧은 용어·폴백 주입은 별도 진단 계층으로 실행한다. 기존 혼합을 변경하지 않는다. 5배·10배의 생성기·qrels·해시를 실행 전에 기록한다.
3. 동일 데이터·장치·버전으로 1/5/10배, 반복 30회 이상, 교차 순서, 연결 유형별 p95와 계측 구간을 실행한다. 성능 우열 전에 운영 9/9 객체 일치, 공개 30·보류 20 회귀 0, 네 정확도 지표 비악화, 후보 누락 0, 색인 갱신·삭제·이름 변경 정합성을 요구한다.
4. 혼합 p95 20%·선택적 3자 이상 30% 개선, 짧은·다건·폴백별 악화 10% 이내, 전체·증분 색인 시간 각 증가 원칙 10% 이내, DB 공간 증가 5% 이내를 확인한다. 공통 성능, 갱신, 복구 적합성은 격리본에서 판정한다.
5. 미실행과 실패를 구분하고 근거·원시 계측·재현 명령·SHA-256을 새 평가 전용 위치에 작성한다. 운영 배포, 서비스 재시작, 공식 대장 변경은 별도 승인 대상으로 둔다.
