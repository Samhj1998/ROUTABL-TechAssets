# 전체 프로세스 경계 설계

1. 외부 래퍼가 Claude 프로세스와 자식에 먼저 적용되게 한다. 해시 고정 실행 파일, 명시 config와 argv, 정규화한 전용 cwd를 사용하고 임의의 fd나 셸 환경을 상속하지 않는다. 실행 전 정책 파일 또는 런타임 누락·오류 시 전체 중단. 무제한 실행 재시도나 설정 자동 대체를 허용하지 않는다.
2. 운영 홈, 원본 저장소, NAS/외장 마운트, 인증 디렉터리를 읽기 정책에서 차단한다. 실제 운용 정책은 필요한 시스템 라이브러리·실행 파일·합성 작업 경로만 열 수 있도록, 접근 가능한 다른 경로와 IPC 예외까지 따로 검증해야 한다. input 읽기만 허용하고 output·scratch 쓰기만 허용한다. 파일 모드 0500 단독으로 같은 UID의 정책 변경을 막을 수 없다. 절대경로, ../, 링크, 대체 마운트 이름과 정규화 후의 실제 경로를 함께 확인한다.
3. Claude 파일 도구에는 restricted와 명시 도구 목록을 추가한다. Bash, MCP, hooks, 플러그인, 자동화, 웹·브라우저 도구는 초기 시험에서 제외한다. 관리 설정이 적용될 수 있으므로 실제 시작 전 허용 도구와 실행 환경을 기록하고 추가 항목이 있으면 중단한다. 정책은 내부 도구와 외부 OS 경계에서 독립적으로 적용한다.
4. 네트워크는 무호출 단계 전체 차단이다. 후속 단계에서는 Pro 요청 후보 api.anthropic.com:443만 우선 검토하고, 이미 로그인한 계정의 토큰 교환/갱신에 필요한 platform.claude.com:443은 별도로 범위를 승인한다. 브라우저 로그인용 claude.ai·claude.com은 별도 인증이 필요한 경우에만 검토한다. 공식 문서상 platform.claude.com은 Pro OAuth 갱신에도 쓰인다. 호스트 허용은 과금 경로나 요청 수를 보증하지 않는다. 승인 외 프록시, wildcard, 임의 localhost, 외부 MCP, Apple Events, 광범위 Mach lookup 또는 보안 완화를 허용하지 않는다.
5. 사용자 토큰, Keychain 내용이나 비밀값을 복사하지 않는다. 원래 사용자의 Keychain을 포괄 허용하지 않는다. 필요한 IPC와 인증 접근만 분리할 수 있는지 확인하고 실패하면 새 표준 사용자·별도 OAuth를 121 Chat에서 결정한다. 인증 경로는 CLI 상태와 과금 화면을 각각 확인한다.
6. 실행 프로세스, 자식, 로컬 프록시와 임시 소켓을 세션 종료 때 정리하고 실제 종료를 확인한다. 전역 설정 대신 승인된 전용 경로에만 설정·로그를 둔다. 승인된 축약 로그와 해시를 보존한다. 임시 경로, 런타임 캐시, macOS 로그 및 후속 OAuth가 발생시킬 수 있는 흔적을 사전 명시한다.
