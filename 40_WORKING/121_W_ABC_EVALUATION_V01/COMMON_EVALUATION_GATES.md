# Step 4-B 공통 합격 게이트와 성능 채택 기준

기준은 같은 Mac Studio에서 재측정하는 A(v1.5)다. 과거 A p95 207.52ms와 합성 정확도는 참고한다. 격리 평가자는 변경 전 DB 해시, Python·SQLite 버전, 앱 모드, 쿼리·페이지 매개변수와 qrels 판본을 실행 전에 동결한다.

## 기능 게이트

1. **운영 회귀 9/9 완전 일치**. 같은 동결 격리 DB·crosswalk에서 전체 반환 객체를 비교한다. 모든 목록 순서와 점수, term/terms, scope, match/group/manual, 페이지 수·번호, 대표·SHA, duplicate_count와 최대 25개 위치, status, provenance를 포함한다. 기본 페이지 외 경계와 마지막/초과 페이지를 검사한다. 실제 질의와 전체 결과는 평가자 전용이다.
2. **합성 개발 30, 보류 20 각각 회귀 0**. 같은 scope·별칭·crosswalk·페이지를 사용한다. Recall, Precision, MRR, nDCG@10을 공통 규격의 경로→그룹 매핑, grade 3/1/0, 중복 반환 0점 및 macro 평균으로 구한다. 네 지표 모두 A 대비 비악화. 질의별 하락과 중복·최신/검증 계약도 각각 확인한다. A에서 이미 실패한 초성은 절대 정확도에 포함해 보고하고 동일 결과를 보존한다.
3. **후보 누락 0**. 활성 분기에서 기존 네 컬럼 SQL LIKE의 모든 rowid가 재검사 전 후보에 포함되어야 한다. 재검사 후의 완전 집합 동등성과 후처리 동등성을 각각 비교한다. 임의 절단, FTS rank 및 후보 LIMIT으로 유효 행을 잃으면 FAIL. 짧은 용어·별칭, escaping, case, Unicode 정규화 및 NUL 회귀를 추가한다.
4. **정합성과 실패 대응**. 같은 세대의 고정 읽기 스냅샷, 정확한 DDL 및 양방향 docs/ft rowid·projection·tags/content 일치를 확인한다. native FTS 검사도 수행한다. 고의 누락·고아·틀린 값·지원하지 않는 DDL·MATCH 오류에서 가속하지 않고 A와 동등한 결과를 반환해야 한다. 격리 초기 색인, 갱신, 삭제, 이름 변경, 무변경, 세대 교체 및 복구 뒤 stale 토큰·old rowid가 없어야 한다. 신규 세대 확인이 비용에 미치는 영향도 계측한다.

## 채택 기준

| 항목 | A 대비 |
|---|---:|
| 전체 혼합 검색 p95 | 20% 이상 개선 |
| 선택도 높은 3자 이상 p95 | 30% 이상 개선 |
| 짧은 검색, 다건 검색, 폴백 검색 p95 | 각 유형의 악화 10% 이내 |
| 전체 색인 생성시간 및 증분 갱신시간 | 각 증가 원칙적으로 10% 이내 |
| DB 저장 공간 | 증가 5% 이내 |

개선율은 `1 - 후보/A`, 악화율은 `후보/A - 1`이다. 10% 원칙을 적용하기 어려운 미세 증분은 절대 지연, paired 분포와 분산을 보고하고 예외 승인 여부를 별도로 표시한다. 기능 FAIL과 성능 채택 미달을 분리한다. A가 0이거나 검증 가능한 표본이 없으면 비율은 미산출하고 원시 측정치를 보고한다.

## 공통 실행 절차

- 동일 장치, 데이터·별칭·scope, 버전과 설정. 1,230 / 6,150 / 12,300건과 평가자 로컬 운영 회귀를 구분한다. 운영 DB 스냅샷이 필요한 시험은 로컬 평가자만 수행한다.
- 질의별 최소 30회, 단일 실행, ABC/ACB/BAC/BCA/CAB/CBA를 6회 순서 블록으로 반복해 위치를 균형화한다. 프로세스 첫 호출, 새 연결, 재사용 연결은 별도 계층이다. A의 기본 query()가 매 호출 새 연결을 여는 점을 보존하고, 동일 계측용 연결 주입에 의한 재사용 실험은 별도 표기한다. OS 캐시를 강제로 비우지 않는다.
- 혼합 집계는 A와 두 후보에서 동일한 유형별 가중치·질의 목록을 고정한다. 기본 합성 비교는 50개 질의 각 동일 반복, 보류가 공개되기 전 목록 해시 동결. 운영 9질의 성능 집계는 별도. 선택적·다건 경계는 A의 일치행 비율로 사전 등록하고, 3자 조건은 모든 확장어 길이로 판단한다. A 기준으로 정의한 짧은/예상 폴백 유형과 후보별 관측 폴백을 함께 공개한다. 작은 유형을 결과 확인 후 통합하지 않는다.
- 평균·p50·p95·최대, nearest-rank, 쿼리별·유형별. SQL 준비/실행·fetch, Python 후처리, 연결 및 직렬화, HTTP end-to-end 구분. 후보수, 세대검증비용, 폴백 사유·비율, 오류·타임아웃 건수와 전체 분모 기록. 폴백이나 오류 표본을 성공 latency에 섞어 숨기지 않는다.
- 동일 시작 이미지와 복제 방식에서 전체 생성, 1건/배치/무변경/삭제/rename을 반복한다. 원본 읽기, 복제, SQL 쓰기, 검증·교체 분리. 닫힌 동일 journal 상태의 DB 바이트와 dbstat 객체별 바이트, 임시 공간 및 sidecar 최대 별도 기록.

후속 준비 상태는 규격 작성 PASS, A/B/C 실측과 채택 판정 NOT_TESTED다.
