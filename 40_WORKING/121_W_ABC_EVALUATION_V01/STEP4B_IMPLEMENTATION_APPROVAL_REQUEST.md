# Step 4-B 독립 구현 승인안

Step 4-A에서 `docs.rowid` 대응 및 조건부 FTS 가능성을 확인했다. 두 구현이 독립적으로 안전한 분기를 만들도록 동일한 사실과 게이트만 전달한다. 평가자 121-W는 양측 원문과 보류 정보를 이미 알고 있다.

## 요청하는 최소 범위

1. `BC_IMPLEMENTATION_INPUT_MANIFEST.md`의 7개 파일을 SHA-256 확인 후 Mac Studio의 두 implementation/input에만 배치한다. 둘 다 같은 판본과 해시를 확인한다.
2. 새 ChatGPT Work 독립 B 세션과 Claude Pro 독립 C 세션에 각자 동일 공통 패킷 및 같은 구현 지시를 제공한다. Claude는 공통 패킷 제공 범위로 한정한다. 평가자 전용 파일·상대 안·코드는 전달하지 않는다.
3. 각자 격리 src/tests/output에서 A 참조의 후보 경로, 현재 스냅샷과 세대 검증, 폴백, 측정 지점과 합성 개발 테스트만 구현하도록 승인한다. 별칭·제목·문자 의미·정렬·그룹·페이지·상태 계약을 그대로 유지한다. 별도 제목 인덱스 또는 운영 갱신 코드 변경은 채택 검토에 남긴다.
4. 각자 구현 파일, 의존성, 실행 방법, 테스트 결과, 변경 범위 및 한계의 SHA-256을 독립 동결한다. 동결 이후 평가자가 Mac Studio에서 공통 시험을 수행할 승인 범위와 동결 출력 위치를 명시한다. 운영 스냅샷은 평가자가 로컬로만 사용한다.

Claude 실행 전 기존 Pro, 승인된 계정, API·외부 게이트웨이 우회 변수 부재, Usage credits 비활성 증거를 재확인한다. 새 과금 경로·결제·크레딧 경고, 인증 비밀·실제 개인정보 발견, 다른 데이터 접근, 입력/원본 해시 불일치나 타 후보 노출 시 해당 작업을 중단하고 기록한다. Step 2-B의 자동 충전 설정값·Console 상태 등은 기존 NOT_TESTED를 보존한다.

## Chat에서 확정할 사항

- 공통 초안 7건의 로컬 배치와 각 AI에의 제공 범위
- 두 독립 세션의 코드/시험 범위 및 출력 동결 방식
- 혼합 집계, 선택도/다건 경계의 실행 전 동결. 합성 50개 각 동일 반복을 기본으로 하며 예시 경계는 A 일치 행이 전체의 1% 이하(선택적), 20% 이상(다건)이다. 운영 9건과 5배/10배는 독립 층으로 보고한다.
- 동결 이후 평가자 전용 회귀·보류·동기화·성능 시험 시작 조건

권장 순서는 공통 입력 동결 → 새 B/C 독립 구현 → 양측 결과 동결 → 동일 장치 공통 시험 → Chat에서 채택 결정이다. 운영 소스, DB, 서비스, 공식 대장과 원본 분석에 대한 변경 승인은 포함하지 않는다.
