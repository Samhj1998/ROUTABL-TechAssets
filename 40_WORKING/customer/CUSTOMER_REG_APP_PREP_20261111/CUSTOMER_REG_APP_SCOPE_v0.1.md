# 고객등록앱 범위 v0.1 (2026-11-11 확정분)

근거: 같은 폴더 `CUSTOMER_REGISTRATION_BASIS_b9c40c2_v0.1.md`

## 개념
- 기사앱의 **고객 등록·목록 부분만 떼어 만든 별도 앱**. 기사앱은 건드리지 않음 (분석앱과 같은 원칙)
- 코드는 기사앱 b9c40c2의 고객 관련 코드를 그대로 가져옴. shared/는 복사 + verifySharedHash
- 새 기능: **다른 배차 앱 화면(캡처·사진)의 글자를 읽어 고객 입력칸을 자동으로 채움**

## 넣는 것
| 기능 | 출처 |
|---|---|
| 고객 목록·검색(초성)·상세 | 기사앱 CustomerListActivity, CustomerSearch, shared/KoreanSearch |
| 신규 등록 입력 화면 | 기사앱 CustomerEditActivity |
| 캡처·사진 → 글자 인식 → 입력칸 자동 채움 | 새로 작성 (ML Kit 한국어, 폰 안에서 처리) |
| 등록 요청 저장 (`customerSubmissions`, pending) | 기사앱 CustomerStore.submit |
| 주소 → 좌표 | 기사앱 CustomerGeocoder 등 |

## 넣지 않는 것
- 배차·정산·영수증 (기사앱 몫)
- 공용 주소록(`customers`) 직접 쓰기 → 확정은 관리자 검수 (지금은 기사앱 관리자 화면)

## 입력 우선순위
- **필수: 업체명, 주소, 전화번호**
- 선택: 동명(주소에서 자동), 도로명주소, 전화2, 찾아가는 길(메모) — 있으면 채우고 없어도 등록 가능
  - 주의: 현재 저장 규칙상 동명과 좌표는 필수 → 주소에서 자동으로 채움

## 글자 인식 → 필드 규칙 (원래 앱 '출발지 상세' 화면 기준)
| 원래 화면 | 필드 | 처리 |
|---|---|---|
| 고객 | name | **`(NNN호X)` 같은 기사 배제 표기는 제거** — 업체명에 붙이지 않음, 저장하지 않음 |
| 전화1 | phone1 | 숫자·기호만 |
| 전화2 | phone2 | `*`는 빈칸 |
| 위치 1줄 | dong | 예: 비산7동 |
| 위치 2줄 | address / roadAddress | `지번(도로명)` 분리, 기존 CustomerAddressPolicy 규칙 |
| 위치 나머지 | memo | 찾아가는 길. **끝의 `*숫자` 표기는 제거** |
| 부서·담당 `*` | — | 무시 |

- 자동 채움 후 **반드시 기사가 화면에서 확인·수정 후 요청**. 자동 제출 없음
- 화면 캡처를 기본 권장 (사진은 반사·손가락으로 오인식 가능)
