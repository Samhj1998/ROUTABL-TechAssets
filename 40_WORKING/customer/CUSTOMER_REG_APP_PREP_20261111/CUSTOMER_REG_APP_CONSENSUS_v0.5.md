# 라우터블고객등록 합의안 v0.5 (2026-11-11 20:00) — 확정

v0.4 대체. 바뀐 점: **"1차 즉시 저장 → 2차 여유 있을 때 정리"** 업무 방식, 공유 버튼 빠른 경로.

## 업무 맥락 (사용자 설명)
- 운전 중 배차가 들어오면 필요한 것은 "지금 그 업체를 출발지로 고를 수 있는 상태". 정확한 업체명·메모·검색어 정리는 5~10분 뒤 여유 있을 때
- 실제 사례: ChatGPT가 은일니트(염색공단요금!!)로 저장 → 그대로 출발지 등록 → 나중에 업체명 정리 → 출발지를 초성검색으로 다시 선정
- 원칙: **클릭 최소화. 바쁠 땐 캡처 하나 던져서 등록, 정리는 나중에**

## 두 가지 경로
- **빠른 경로 (공유)**: 인성데이타·갤러리·카톡에서 캡처 "공유" → 라우터블고객등록 선택 → 앱 화면 없이 1차 등록 → 결과는 알림 한 줄
- **정식 경로**: 앱 열기 → "캡처로 등록" → 파일 선택(여러 장 가능) → 자동 1차 등록 → 완료 화면 (되돌리기·수정)
- 직접 입력도 유지 (시간 여유 있을 때)

## 로그인·권한 (2026-11-11 20:06 추가, 기사앱 그대로)
- 기사앱·분석앱과 같은 구글 로그인 → 서버 `users/{uid}.approved` 확인. 미승인은 "승인 대기" 화면만 (등록 버튼 없음)
- 실제 방어선은 서버 규칙(firestore.rules, 변경 없음): `customers` 쓰기 = 관리자 UID만 / `customerSubmissions` 생성 = 승인 기사(approvedDriver)만 → 앱만 깔아서는 쓰기 불가
- Firebase 앱 등록 + SHA-1 등록된 서명 앱만 구글 로그인 가능
- 관리자 → 공용 주소록 바로 / 일반 기사 → 등록 요청, 승인 전에는 본인 목록에만 "승인 대기"로 보이고 본인은 바로 사용 (기사앱 CustomerDirectory 본인 요청 병합 코드 재사용, 기사앱에도 같이 보임)
- 공유 경로: 로그아웃·미승인 상태면 저장 안 하고 "로그인이 필요합니다" 알림
- 신규 기사 가입·승인 신청은 기사앱에서. 고객등록앱은 승인된 기사 전용 도구

## 1차 등록 (멈추지 않음)
- 글자 인식 → 칸 나누기 → 좌표 → 중복 검사 → **조건이 일부 안 맞아도 저장**, 미심쩍은 점만 기록
- 멈추는 경우(저장 불가)만: 업체명 못 읽음 / 주소로 좌표 못 찾음 → 알림 "등록 못 함: 이유" + 정리 목록에 남김
- **중복 발견 시 아무것도 쓰지 않음** → 알림 "이미 있음: 업체명" (기존 고객으로 바로 배차 가능). 보완(전화 추가 등)은 정리 목록으로
- 관리자(pyh1772@gmail.com) = 바로 저장 / 다른 기사 = 등록 요청 자동 전송 (검수는 기존대로)

## 2차 정리 ("정리할 고객" 목록)
- 1차에서 미심쩍었던 건, 미뤄 둔 보완 건, 등록 못 한 건이 모임 (앱 첫 화면 배너)
- 열면 수정 화면 (기사앱·고객앱 수정 화면과 같은 방식) / 보완 건은 바뀐 칸만 표시 → 저장하면 목록에서 빠짐
- 목록은 폰 안에만 저장. 고객 주소록 구조 변경 없음

## 정리 규칙 (v0.4 그대로)
- 필수: 업체명·주소·전화. 업체명이 아닌 표기 → 메모. (NNN호X)·끝 `**`·위치 끝 `*숫자` 버림. 다른 상호 괄호는 유지
- 메모 첫 줄 "도로명주소: …", 나머지 형식 자유. 추가 전화는 메모에 번호만. 보완 시 메모는 덧붙임
- 글자 인식: ML Kit (폰 안)
