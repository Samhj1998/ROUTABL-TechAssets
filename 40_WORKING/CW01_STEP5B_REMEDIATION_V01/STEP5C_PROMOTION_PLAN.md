# CW-01 Step 5-C 공식 승격 계획안

상태는 검토 및 승인 대기다. 아래 경로는 저장소 기준 상대경로다.

| 신규 공식 문서 제안 | 등록 후보 ID | 제안 경로 |
|---|---|---|
| 인계 출력 계약 v0.2 | ASSET-120-CW01-OUTPUT-CONTRACT-V0.2 | 00_GUIDE/DIGITOPIA_CW01_HANDOFF_OUTPUT_CONTRACT_v0.2.md |
| 기술자산 접근 정책 v0.2 | ASSET-120-CW01-ACCESS-POLICY-V0.2 | 00_GUIDE/DIGITOPIA_CW01_ACCESS_POLICY_v0.2.md |

증거 계보 보완과 종료·검증 문서는 승격 근거로 연결한다. 기존 CW-01 후보 ASSET-120-CW01-PROTOCOL-V1.0의 등록은 이번 계획에 포함하지 않는다. 현 후보 ID는 27개 기존 대장 텍스트에서 동일 문자열을 발견하지 않았으며 목적지 두 파일과 v0.28 경로도 비어 있었다. 이 점검은 정식 발급이 아니며 승격 직전 구조화된 ID·경로·해시 중복 점검을 다시 한다. 동일 계보의 기존 ID가 확인되면 Chat에서 매핑을 결정한다.

1. 별도 승인을 받는다. 대상 문서와 승인할 바이트·SHA-256, 공식 목적지, 등록 ID, 새 대장 판본, 승인 증빙 및 실패 시 처리를 명시한다. 공식본 표지나 상태를 바꾸는 경우 변경된 최종 바이트와 해시를 승인 대상으로 제시한다.
2. 직전 최신 대장과 기존 정책·원칙·후보의 SHA-256, 경로 충돌·중복 ID를 기록한다. 기존 판본을 덮어쓰지 않고 신규 공식 파일을 별도 경로에 작성한다. 심볼릭 링크와 하드링크 의존 없이 배포한다.
3. 최신 대장이 v0.27로 유지되면 30_REGISTRY/asset_manifest_v0.28.json을 신규 판본으로 제안한다. 선행 판본과 증거 계보, 공식 경로와 실측 해시, 검토자·승인·시각을 기록한다. 선행 판본이 바뀌면 다시 대조하고 다음 번호를 확정한다.
4. 공식 파일 바이트 및 SHA-256, 대장 JSON 유효성·ID 유일성·참조 경로 일치, 기존 판본과 보호 대상의 전후 불변성을 대조한다. 두 파일을 검증하기 전에는 새 대장을 게시하지 않는다. 등록만으로 검색 색인·DB·운영 적용·백업 복원을 완료 처리하지 않는다.
5. 실패 시 다음 게시를 중단한다. 대장 게시 전에는 v0.27을 그대로 운영 기준으로 유지하고, 부분 생성물은 미승격으로 식별한다. 게시 후라면 실제 최신 판본 선택 방식부터 확인한 뒤 승인된 후속 정정 판본으로 기존 유효 상태를 복원하는 방안을 검토한다. 새 파일 이동·삭제와 활성 판본 변경은 승인된 되돌리기 범위에서만 수행하고 이력을 보존한다.

CW-01 v1.0의 인계·승인 원칙을 보완하고, TI-01의 보존·복구 우선순위 및 VI-01의 판본 독립·공통 원본 분리를 따른다. 기존 보안·검색 정책은 색인과 민감정보 제한의 기준으로 적용한다. 변경된 권한이나 새 검색 범위의 운영 적용은 별도 작업이다.
