# 고정 해시 및 승인 설정 영향

| 구성요소 | 보존할 기존 자산 | 운영 도입 시 필요한 결정 |
| --- | --- | --- |
| 감독자 | ROUTABL_BackupHeadlessSupervisor_v0_1.py, ROUTABL_BackupHeadlessSupervisor_v0_2.py | 신규 감독자 판본과 경로를 추가한다. 단계별 증거 및 새 상태 계약을 사용한다. |
| OneShot | ROUTABL_MacToNasOneShot_v0_1.py | 신규 판본/어댑터로 구조화된 실제 실행 여부와 잠금 소유권을 전달한다. 기존의 종료값만 전파하는 경로는 신규 예약에서 연결하지 않는다. |
| 로컬 Gate | ROUTABL_HeadlessDailyGate_v0_3.py | 결과 필드와 내부 잠금이 새 어댑터 수용 기준을 충족하면 기존 바이트를 유지한다. 필드 보강이 필요하면 신규 판본과 핀이 필요하다. |
| 로컬 선택기 | ROUTABL_SelectiveSecureBackup_v2_1.py | 재사용 우선. 164개 대장 등록 건과 실제 선택 건수를 구분하며 운영 선택 범위·한도는 별도 검증한다. |
| NAS CAS | ROUTABL_NAS_ContentAwareBackup_v0_2.py | CAS 재사용·신규 복제 의미를 어댑터에서 증명할 수 있으면 기존 바이트 유지. 수정이 필요하면 새 판본과 핀이 필요하다. |
| 네이티브 에이전트 | native.v042, native.v02 및 각각의 관리자 앱 | 신규 감독자 경로·해시와 명시적 상태 계약을 이해하는 서명된 신규 안정판 후보가 필요하다. 이전 두 등록을 정리하고 신규 1개만 남긴다. |

기존 approval_v01.json의 검증 규칙은 OneShot, NAS 엔진, 로컬 Gate의 SHA-256을 확인한다. 신규 OneShot 경로·해시를 기존 승인으로 자동 수용할 수 없다. 운영판이 어댑터를 별도 파일로 두면 그 실행 파일도 핀 검증 범위에 추가한다. 동일 바이트를 쓰는 Gate와 NAS 엔진은 재해시 후 기존 핀을 재사용할 수 있다. 설치 v042 에이전트는 감독자 경로와 해시를 고정하므로, 감독자 교체만 하면 에이전트 차단이 예상된다. 새 배포 앱의 서명·등록·승인·권한과 정확한 경로 및 SHA-256을 서명 완료 후 확인한다.

승인 파일 내용과 비밀은 조사하지 않았다. 새 운영판은 권한 범위와 실행 시각, 무삭제 등 기존 승인 제한을 보존해야 한다. 등록·고정 해시 변경, 코드 서명, 배포, 이전 예약 비활성화, 수동 실제 백업은 B3 밖의 별도 승인이다.
