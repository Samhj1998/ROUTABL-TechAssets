# B5 영수증 정규화 설계

정규화기는 입력 바이트를 비교하는 순수 함수다. 운영 파일 경로를 열거나 엔진을 호출하지 않는다. 실제 점검 래퍼는 고정된 읽기 전용 파일에서 최신 대장·로컬 상태·OneShot 보고서·해당 CAS 매니페스트만 읽고 결과를 마스킹된 JSON으로 보존한다.

| 항목 | 출처와 검증 규칙 |
| --- | --- |
| 최신 대장 | 30_REGISTRY의 최신 숫자 판본과 원문 SHA-256. 이름과 SHA가 모두 일치해야 현재 대장이다. |
| 선택 목록 | 상태의 selection_sha256, file_count, source_bytes는 보고값이다. 원본 snapshot_receipt.json이 허용되면 records의 상대경로·SHA·크기·분류를 정렬하고, UTF-8 JSON 배열 한 줄과 LF를 이어 SHA-256을 재계산한다. 선택 건수·총바이트·summary 및 source_manifest 별칭을 별도로 대조한다. 현재 선택 목록을 증명하려면 승인된 독립 인벤토리와 세 값 모두 비교한다. |
| 로컬 스냅샷 | KST 기준 생성일과 시각, ASSET_V21 식별자, 상태의 SUCCESS·잠금·SHA 플래그를 확인한다. 원본 영수증 바이트가 있으면 상태의 receipt_sha256과 연결한다. 원본 영수증 자체도 매체 전체 파일을 새로 읽었다는 증거는 아니다. |
| CAS | 완료된 매니페스트의 이름·스냅샷·로컬 영수증·대장·선택 해시를 OneShot 및 로컬 상태와 연결한다. 구성요소 이름 중복·경로·reference 유형·건수·크기를 검사한다. 명시된 anchor 경로는 문자열만 검증한다. |
| 전체 구성요소 | 과거 OneShot v0.1 소스에는 full=True 검사 조건이 있다. 보고서의 성공 주장은 해당 메타데이터와 연결되지만, 그 실행 시점의 코드와 모든 구성요소의 실측을 B5에서 다시 입증하지 않았다. 신규 검증 영수증에는 매니페스트 SHA, 선택/로컬 영수증 SHA, 검증 시작·완료 시각, 검증기 SHA, 검증한 구성요소 건수·바이트, 완료 상태가 함께 필요하다. |

구조·계보가 맞는 경우 정규화 결과는 PARTIAL이다. 최신 대장 또는 당일 기준 미일치는 별도 표시한다. JSON 중복 키, 필수 필드 누락, 시각 역전, 참조 불일치 등은 FAIL이다. 이 후보에서는 실제 백업 성공을 출력하지 않는다.

현재 NAS CAS 목록의 구성요소 합계는 585개, 4,851,127,156바이트다. 이 스냅샷만 전체 검사해도 참조 항목 기준 약 4.85GB와 수백 건의 SMB 파일 열기/조회가 발생한다. anchor와 blob을 모두 해석하고, 반복 참조·읽기 실패·경로 교체·검증 중 작업 경합을 제어해야 한다. 현재 엔진 CLI verify는 전체 이력을 검사하므로 별도 승인 시에도 대상 매니페스트 SHA 고정, 파일 접근 범위, 시간·대역폭 한도, 중단·재시도 규칙을 정해야 한다.

원본 로컬 영수증은 닫힌 암호화 이미지 안에 있다. B5에서 이미지에 접근하거나 마운트하지 않았다. 이후 운영 후보는 정상 백업 중 영수증 바이트를 해시하는 기존 경로에서 최소 요약과 원본 해시를 증거로 내보내는 방식 또는 별도로 승인된 원본 대조 절차를 설계해야 한다.
