# native.v043 배포·전환·롤백 계획

현재 단계는 격리 후보다. 운영 구성에는 감독자 v0.3, OneShot v0.2, 증거 어댑터 v0.1, 모든 코드 의존성 및 실제 정규화 어댑터를 별도 승인된 신규 경로로 배치하는 단계가 필요하다.

1. 서명 전에 번들 ID, Team ID, 지정 서명 요건, SMAppService 작업 라벨, 승인 경로와 유효 UID를 정한다. 예약과 수동 실행이 같은 감독자와 동일한 잠금 inode를 사용해야 한다. 기존 직접 실행 경로를 폐쇄한다.
2. 별도 승인된 서명·빌드 후 codesign strict 검증, 지정 서명 요건 및 Team ID 대조, 에이전트와 감독자의 바이트 SHA-256을 확인한다. 배포 경로와 상위 디렉터리는 승인된 소유자와 쓰기 권한으로 보호한다. 현재 후보의 실행 전후 해시만으로 import 이후 변경, 해시-실행 간 교체 또는 원상복귀 경쟁을 차단할 수 없다. 실제 에이전트가 Python 실행 전에 감독자·의존성 바이트와 승인 파일을 검증해야 한다.
3. 04:30 창 밖에서 진행한다. v02 해제 후 v042 단독 상태를 확인한다. 신규 v043을 사전 검증하고 v042를 해제한 뒤 v043을 등록한다. 두 라벨이 동시에 활성화되는 구간을 허용하지 않는다. 등록 직후 읽기 전용으로 단일 라벨과 달력 설정을 확인한다.
4. 에이전트는 JSON status, scope, run_id 및 보고서 시각, 최신 대장·선택 SHA, 로컬·CAS 계보를 검증한다. exit 0은 NEW, 10은 당일 기존 증거 재검증, 20은 잠금 스킵, 30은 비성공을 뜻한다. 알 수 없는 상태 또는 종료값 불일치는 실패 처리한다. ISOLATED_FIXTURE_ONLY 보고서는 운영 성공으로 받아들이지 않는다.
5. 운영 실패 시 신규 v043부터 등록 해제하고 잠금과 자식이 정리됐는지 확인한다. 사전 승인된 기존 서명 v042 단일 구성과 이전 핀으로 복귀할 수 있다. v02를 함께 복원하지 않는다. 안전한 단일 복귀가 불가능하면 예약을 중지하고 120-2 Chat에 반환한다. 기존 스냅샷과 영수증을 보존한다.

승인 스키마는 PROPOSED_INACTIVE이며 비밀을 포함하지 않는다. B4 가상 승인 파일과 운영 승인 파일은 별개다. 실제 승인 파일 변경, 서명, 배치, 등록, 예약 변경, 운영 백업 실행은 모두 별도 승인 범위다.
