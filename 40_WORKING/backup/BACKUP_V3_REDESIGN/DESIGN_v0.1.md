# 라우터블 기술자산 자동 백업 v3 재제작 설계안 v0.1 (2026-11-14, 승인 전)

## 왜 다시 만드나 (근거)
1. **실패해도 이유가 안 남는다:** 감독자가 하위 출력을 버림(DEVNULL), 하위는 오류 이름만 남기고 exit 2. 11-14 실패 원인 특정 불가.
2. **시작 경로가 5단계:** 관리자 앱 → SMAppService 예약 → Swift 실행기 → Python 감독자 → SHA 고정 스크립트 3개 → 실제 백업 2개. 한 단계만 어긋나도 멈춤.
3. **예약이 조용히 사라진다:** 11-12~13 사이 예약 해제, 실패 기록조차 없음(11-13 발견).
4. **복구가 막힌다:** 승인 파일이 있으면 재등록 거부 → 승인 파일을 옮겼다 되돌리는 수작업 필요.
5. **버전이 겹친다:** v02·v0.4·v0.4.1·v0.4.2 앱이 동시에 켜져 있었음.

## 그대로 살릴 것 (검증된 부분)
- 실제 백업 로직: 선택 백업 → AES-256 SSD 이미지 → SHA 검증 → 표본 격리 복원 → NAS 암호화 CAS 사본. 11-12 22:58 수동 실행 성공(1,830개, 표본 15개 복원).
- 원칙: 비밀값을 기록·색인에 넣지 않음, 실패 시 재시도 없이 안전 종료, 기존 스냅샷 삭제 금지.

## 새 구조 (단순화)
```
launchd 예약 1개 (com.routabl.backup.v3, 04:30)
  └─ backup_v3.py 1개
       1. 사전 점검: SSD·NAS 마운트, 이미지 잠금 상태, 디스크 여유
       2. 로컬 백업 (기존 검증 로직 호출)
       3. NAS 사본 (기존 CAS 로직 호출)
       4. 검증: SHA·표본 복원
       5. 결과 기록 (항상)
```
- **모든 실행에서 기록 1줄 이상:** `runs.jsonl`에 시작·단계별 결과·실패 사유 코드·소요시간을 추가 기록. 하위 출력은 버리지 않고 사유 코드만 추출해 남김(비밀값 필터).
- **아침 점검 (09:00):** 오늘 기록이 없거나 실패면 macOS 알림 + 상태 파일 표시. 예약이 사라졌는지도 이때 확인.
- **승인 방식:** 승인 파일은 "실행 허용 여부" 하나만 담음. 예약 등록과 무관 → 재등록이 막히지 않음.
- **무결성:** 스크립트 SHA 고정은 유지하되, 불일치 시 사유를 기록하고 알림(조용히 멈추지 않음).
- **단일 버전:** 설치 시 옛 예약·앱(v02, v0.4.x) 비활성 확인을 설치 점검 항목에 포함.
