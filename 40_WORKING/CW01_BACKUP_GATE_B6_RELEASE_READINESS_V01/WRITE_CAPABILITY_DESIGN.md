# 전용 매체 쓰기 자격과 현행 우회 경로

Mac Studio의 관찰 UID는 501이다. SSD sparsebundle, NAS 마운트와 NAS snapshots 디렉터리는 이 UID 소유이며 관찰한 관련 디렉터리 모드는 0700이다. 이는 다른 UID의 접근을 현재 보장하지 않으며, 같은 UID의 경쟁 프로세스를 격리하지 않는다. macOS 클라이언트의 소유권·os.access는 NAS 서버 ACL, SMB 세션 신원, 키체인 접근, TCC 승인 또는 실제 쓰기 권한의 독립 증거로 사용하지 않는다. Keychain 비밀 조회 및 TCC DB 열기는 범위에서 제외했다.

| 대안 | 실현 가능성 및 검증 조건 |
| --- | --- |
| 전용 비관리 실행 UID와 SSD/NAS 쓰기 자격 | 우회 차단에 가장 직접적이다. 그러나 NAS 서버 전용 계정/ACL, SSD 및 이미지 내부 소유권, 전용 세션의 비대화형 키체인·TCC, 읽기 소스 및 상태 경로가 필요하다. 기존 Supervisor와 OneShot은 UID 501 고정이며 선택기는 하드코딩 경로와 상태 디렉터리 소유권을 검사한다. 변경 없는 호환성은 미검증이다. |
| 서명된 서비스와 인증 IPC | 예약과 수동 요청의 단일 진입점이 될 수 있다. IPC의 peer audit token, 승인된 코드 서명·UID·호출 범위, nonce와 리플레이 차단을 검증한다. 별도 저장 매체 쓰기 권한이 있어야 동일 UID 직접 쓰기까지 막을 수 있다. 서명 또는 IPC만으로 매체 쓰기를 보호하지 않는다. |
| 기존 엔진의 새 쓰기 진입부 | 전용 UID와 경로를 주입하거나 서비스가 발행한 권한을 검증할 수 있다. 기존 쓰기 엔진이 매체에 계속 직접 접근할 수 있으면 기존 바이트가 우회로가 된다. 레거시 쓰기 자격의 제거와 실제 차단 실증이 필요하다. |
| 기존 진입 경로 접근 제한 | 운영 승인 후 구 등록과 수동 런처를 제한한다. 스크립트 실행 비트나 flock만으로 같은 UID가 Python으로 실행하는 것을 차단할 수 없다. 보관 경로를 유지하고 운영 저장 매체 접근을 분리한다. |

OneShot, Gate, SelectiveSecureBackup, CAS와 별도 NAS 복제는 운영에서 각자의 잠금을 사용한다. 레거시 native.v02/v042도 신규 공통 잠금을 소유하지 않는다. **현행 상태 BYPASS_NOT_BLOCKED.** 실제 쓰기는 시도하지 않았다. 격리 시험에서 같은 UID의 직접 쓰기와 가상 쓰기 자격 거부를 각각 확인했다.

운영 수용에서는 비인가 계정·레거시 직접 호출이 매체에 쓰지 못함을 승인된 무해한 대상에서 확인하고, 인가 서비스만 같은 보호 inode의 공통 잠금을 잡아 쓸 수 있어야 한다. SSD/NAS·계정·ACL·Keychain·TCC 또는 서비스 등록 변경과 실제 쓰기 검증은 각각 별도 승인 대상이다.
